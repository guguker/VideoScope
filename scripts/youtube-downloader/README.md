# Загрузчик YouTube для macOS

В корне проекта дважды нажмите **«download-youtube.command»**. При первом запуске скрипт соберёт отдельное нативное окно macOS; последующие запуски используют готовое приложение. Пересборка происходит при изменении исходников или компилятора. Сервер VideoScope запускать не требуется.

1. Вставьте ссылки на видео YouTube — по одной на строку, до 50 за раз.
2. Выберите качество и формат, при необходимости включите субтитры или обложку.
3. Начните загрузку. Файлы сохраняются в папку **«Данные матчи»** в корне проекта; её можно открыть из окна загрузчика.

Папка загрузок и служебная `.youtube-downloader/` исключены из Git. Скрипт не индексирует загруженные видео и не использует их для обучения. Основной путь VideoScope не изменяется; работа над ML-фазами этим скриптом не запускается.

## Возможности

- Очередь отдельных видео и выбор максимального разрешения. Если выбранное разрешение недоступно, загружается лучшее доступное ниже этого предела. Ссылки с параметром плейлиста скачивают только указанное видео; целые плейлисты и текущие прямые эфиры не поддерживаются.
- Видео в MP4 или MKV, либо только звук в M4A или MP3. MP4 задаёт контейнер: видео максимального качества может использовать AV1/VP9, поэтому совместимость с QuickTime не гарантируется. Для таких файлов подойдёт проигрыватель с поддержкой соответствующего кодека.
- Русские и английские субтитры, включая автоматические при включении соответствующей настройки, и обложка сохраняются рядом с видео, если доступны на YouTube.
- Прогресс, журнал загрузки и отмена. Отмена оставляет частично загруженные файлы: повторная загрузка с теми же настройками по возможности продолжает их. Продолжение зависит от доступности прежнего формата и потока на YouTube.
- Cookies браузера используются только после ручного выбора этой опции. Она может помочь с видео, для которых требуется вход; macOS может запросить доступ к данным браузера. По умолчанию cookies не читаются.
- Для Arc выберите **Arc**: загрузчик передаст читателю Chromium отдельную папку `~/Library/Application Support/Arc/User Data`. Обычный пункт Chrome использует профиль Chrome. При нескольких профилях Arc `yt-dlp` выбирает самую недавно изменённую базу cookies. В некоторых версиях Arc расшифровка cookies может не работать — это [известная проблема yt-dlp](https://github.com/yt-dlp/yt-dlp/issues/7805). Если журнал сообщает `cannot decrypt` или `no key found`, используйте другой поддерживаемый браузер, в котором вы вошли в YouTube. Поддержка Arc проверена тестами формирования команды; чтение ваших cookies и загрузка с ними при разработке не выполнялись.

Настройки применяются к очереди при старте. Загрузка начинается только после действия в окне. Уже загруженные файлы сохраняются; скрипт не очищает папку.

## Зависимости и обновление

Нужны macOS, инструменты разработчика Apple со Swift, `yt-dlp`, `ffmpeg`/`ffprobe` и Node.js. Скрипт сам не устанавливает и не обновляет программы. При необходимости:

```sh
xcode-select --install
brew install yt-dlp ffmpeg node
```

Homebrew должен быть установлен заранее. Для отдельной копии `yt-dlp` внутри проекта выполните из корня проекта (нужен Python 3):

```sh
python3 -m venv .youtube-downloader/runtime
.youtube-downloader/runtime/bin/python -m pip install 'yt-dlp[default]==2026.8.19'
```

Если такая копия существует, приложение использует её в первую очередь. Она хранится в исключённой из Git папке и не меняет пакеты VideoScope или глобальную установку Homebrew. Если YouTube перестал отдавать видео, локальную копию можно обновить вручную:

```sh
.youtube-downloader/runtime/bin/python -m pip install --upgrade 'yt-dlp[default]'
```

Если локальной копии нет и используется Homebrew:

```sh
brew upgrade yt-dlp
```

Node.js используется для JavaScript-проверок YouTube. Подробности: [официальная документация yt-dlp](https://github.com/yt-dlp/yt-dlp#readme) и [поддержка JavaScript/EJS](https://github.com/yt-dlp/yt-dlp/wiki/EJS). Изменения YouTube, ограничения доступа и сети могут влиять на загрузку.

## Проверка без скачивания

Из корня проекта:

```sh
./'download-youtube.command' --check
swiftc -swift-version 5 -module-cache-path .youtube-downloader/module-cache \
  scripts/youtube-downloader/DownloadCore.swift \
  scripts/youtube-downloader/tests/core-tests.swift \
  -o .youtube-downloader/core-tests
.youtube-downloader/core-tests
swiftc -swift-version 5 -module-cache-path .youtube-downloader/module-cache \
  scripts/youtube-downloader/DownloadCore.swift \
  scripts/youtube-downloader/CommandRunner.swift \
  scripts/youtube-downloader/tests/runner-tests.swift \
  -o .youtube-downloader/runner-tests
.youtube-downloader/runner-tests
git diff --check
```

`--check` проверяет зависимости и собирает приложение, не открывая окно и не обращаясь к YouTube. Тесты проверяют локальную обработку ссылок, формирование команд и управление процессами, включая отмену; они не подтверждают доступность конкретного видео на YouTube.

Проверка на этом Mac 11 сентября 2026: сборка и подпись приложения, 145 проверок core и тесты процессов прошли. С локальным `yt-dlp 2026.08.19` проверено реальное скачивание короткого ролика в MP4; `ffprobe` подтвердил видео и звук. Через окно проверена очередь из недоступного и доступного видео: ошибка первой ссылки не помешала сохранению второй в «Данные матчи». Тестовый файл перенесён во временную папку. Другие контейнеры и выбор разрешения проверены на синтетических метаданных; реальные многочасовые видео, субтитры и вход через браузер в этой проверке не использовались. ML-проверки VideoScope не запускались: утилита не меняет его код и артефакты.
