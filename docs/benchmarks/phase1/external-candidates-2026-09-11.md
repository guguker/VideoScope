# Готовые баскетбольные данные и модели: аудит публичных описаний

Дата: 2026-09-11. Статус: кандидаты для Фазы 1, не импортированный dataset и не
принятые модели. Проверялись публичные статьи, README и dataset/model cards.
Видео, архивы разметки и веса не скачивались; пользовательские материалы не
отправлялись наружу. Доступность ссылки на веса не доказывает содержимое бинарника,
воспроизводимость результата или совместимость с M4 Pro.

Датасет бывает размеченным; модель — обученной. Для VideoScope нужны оба вида
артефактов, но они проходят разные проверки. Название задачи, опубликованный код
и готовый checkpoint не взаимозаменяемы. Ранжирование ниже — оценка соответствия
нашим задачам, а не результат локального benchmark.

## Приоритетные кандидаты

| Кандидат | Соответствие задаче | Что опубликовано | Что ограничивает применение |
| --- | --- | --- | --- |
| **BARD / E-BARD** | События, номера игроков, команды по цвету, передавший; отдельно мяч/кольцо/игрок/судья | BARD сообщает 14 676 итоговых клипов из 60 NBA-матчей. Структурированные описания содержат `player`, `action`, `result`, `assisted`, `other_player`, `color`. E-BARD добавляет detection/JNR и готовые специализированные веса | Основная BARD-разметка строится из play-by-play, вручную проверена подвыборка; весь набор не human-gold. Внутренние границы каждого действия требуют отдельной проверки. Cards заявляют CC BY 4.0; это не устанавливает все права на исходные трансляции и базовые модели. [Данные](https://huggingface.co/datasets/GabrieleGiudici/BARD), [структура событий](https://github.com/GabrieleGiudic/BARD) |
| **SportsHHI** | Пары игроков: передача/приём, блокировка и помеха броску, перехват, проход/защита, варианты заслона | 16 баскетбольных классов; кадры, рамки и ID участников взаимодействия; код обучения/оценки. Это наиболее прямой проверенный кандидат для защитных взаимодействий | CC BY-NC 4.0, доступ после принятия условий. ID относится к человеку в сцене, не к номеру в заявке. Полноценные схемы всей защиты и прогноз её действий не следуют из этих меток; готовый финальный checkpoint в просмотренном README не подтверждён. [Dataset card](https://huggingface.co/datasets/MCG-NJU/SportsHHI), [статья и классы](https://arxiv.org/html/2404.04565v1), [код](https://github.com/MCG-NJU/SportsHHI) |
| **SportsMOT / MixSort** | Непрерывное отслеживание игроков в спортивных трансляциях | SportsMOT: 240 последовательностей трёх видов спорта, включая баскетбол; bbox и track IDs. MixSort публикует model zoo обученных весов | SportsMOT — CC BY-NC 4.0 и дополнительные условия доступа/распространения. Нет меток мяча, персональных опекунов или схем защиты. GPU-ориентированная установка; перенос на M4 и безопасная загрузка `.pth.tar` не проверены. [Данные](https://github.com/MCG-NJU/SportsMOT), [обученные модели](https://github.com/MCG-NJU/MixSort#model-zoo) |
| **DeepSportradar** | Геометрия площадки, калибровка камеры; отдельные задачи мяча, segmentation и ReID | Калибровочный baseline, 728 пар «изображение/калибровка» по README и ссылка на обученные веса | Keemotion undistorted views и FIBA-площадки не тождественны движущейся broadcast-камере UBA. Basketball Instants card — CC BY-NC-SA 4.0; лицензии отдельных инструментов/весов проверяются отдельно. Защитных меток нет. [Калибровка](https://github.com/DeepSportradar/camera-calibration-challenge), [данные](https://www.kaggle.com/datasets/deepsportradar/basketball-instants-dataset) |

## Какие обученные модели действительно найдены

- **E-BARD YOLOv8n и RF-DETR Nano**: автор публикует специализированные checkpoints
  для четырёх сущностей. Их результаты не идеальны даже на авторском тесте:
  basketball recall при IoU 0.5 указан как 0.566 и 0.322 соответственно. Это повод
  проверить именно пропуски мяча, а не ожидать готового надёжного tracking.
  Эти цифры не сравниваются напрямую с VideoScope Recall@K.
  [Model card](https://huggingface.co/GabrieleGiudici/E-BARD-detection-models).
- **EBQwen2.5-VL-3B**: опубликованы safetensors для basketball action recognition,
  номеров, цветов и grounding. Автор отдельно указывает трудности плотной
  детекции и смещение к NBA. Это кандидат для сравнения с текущим verifier;
  имя «basketball» не является доказательством улучшения на UBA или основанием
  замены действующего Qwen. [Model card](https://huggingface.co/GabrieleGiudici/EBQwen2.5-VL-3B).
- **MixSort и DeepSportradar calibration baseline**: есть авторские ссылки на
  обученные веса; содержимое, хеши и исполнимость этих файлов здесь не проверялись.
  Калибровочный baseline при нехватке пересечений линий использует средние параметры
  камеры. Такой fallback нельзя представлять как подтверждённую геометрию кадра.
  [MixSort](https://github.com/MCG-NJU/MixSort#model-zoo),
  [calibration baseline](https://github.com/DeepSportradar/camera-calibration-challenge).

## Дополнительные варианты и границы уверенности

- **TrackID3x3**: покадровые рамки шести игроков и часть pose-разметки; полезен для
  identity/tracking. README явно разделяет CC BY 4.0 на dataset, Apache 2.0 на
  основной код и CC BY-NC 3.0 на jersey-number-pipeline. Формат 3×3 и фиксированные
  камеры требуют отдельной проверки переноса на 5×5 broadcast.
  [Репозиторий авторов](https://github.com/open-starlab/TrackID3x3).
- **TeamTrack**: полное поле и траектории на площадке полезны для пространственного
  анализа; фиксированные камеры и полное покрытие отличаются от UBA-трансляций.
  Готовый отдельный checkpoint и применимость лицензии репозитория к медиаданным
  в этой проверке не подтверждены. [Репозиторий](https://github.com/AtomScott/TeamTrack).
- **FineSports**: детальные действия, границы и рамки целевого игрока; данные
  выдаются по Release Agreement. Финальные обученные PoSTAL-веса и точные условия
  соглашения в этой проверке не установлены. [Репозиторий](https://github.com/PKU-ICST-MIPL/FineSports_CVPR2024).
- **NETS**: получает уже готовые координаты десяти игроков и мяча. Использованные
  632 NBA-матча не означают 632 матча с ручной разметкой защиты: задачи —
  pick-and-roll/handoff/other, значительная часть меток слабая. Доступность полного
  авторского комплекта данных/меток/весов не подтверждена; указанный авторами
  GitHub-адрес при проверке вернул 404. [Статья](https://arxiv.org/abs/2209.00451).
- Есть прямое исследование распознавания **switch/trap против pick-and-roll** по
  SportVU. Оно показывает подход, но в этой проверке не найден публичный комплект
  gold-video-labels и готовых весов под нашу трансляцию.
  [Первичная публикация](https://www.mdpi.com/2076-3417/10/1/24).

BARD Viewer показывает 24 692 первоначальные строки при заявленных 14 676 итоговых
клипах. У E-BARD Detection card сообщает 1 800 кадров, а Viewer — 8 666 строк и
ошибку обработки. Эти расхождения требуют аудита реального архива и schema;
они не доказывают ни порчу всего набора, ни готовность его к импорту.
[BARD](https://huggingface.co/datasets/GabrieleGiudici/BARD),
[E-BARD Detection](https://huggingface.co/datasets/GabrieleGiudici/E-BARD-detection).

## Решение для VideoScope

Первыми кандидатами предметного аудита оставить **BARD/E-BARD** для событий и
участников, добавить **SportsHHI** для взаимодействий. **SportsMOT/MixSort** и
**DeepSportradar** рассматривать как источники компонентов tracking/geometry.
Для «кто кого опекал, смена или помощь, начало/конец, реакция на заслон» предусмотреть
собственный человеческий annotation contract и доказательства на UBA. Прогноз
требует отдельного горизонта и проверки без будущих кадров/исхода в признаках.

Ни один проверенный источник не покрывает весь путь
`UBA broadcast → участники/траектории → защита → запрос → точный интервал → MP4`.
Готовые компоненты могут уменьшить объём собственной разработки и разметки;
восемь UBA-источников остаются данными нашего домена, а не лишней работой из-за
наличия NBA-корпуса. Решение отложить пользовательскую подборку NBA сохраняется.

Перед фактическим использованием кандидата нужны конкретный источник/ревизия,
состав и условия доступа, происхождение/группы, права на выбранное использование,
а для весов — безопасный формат, runtime и измерение на M4 Pro. Это существующие
gates проекта, не новые разрешения. Сейчас не выполнялись импорт, обучение,
новая модельная оценка или изменение active. Phase 0 baseline/rollback сохранены;
полный data exit gate Phase 1 остаётся открытым.
