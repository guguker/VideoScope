# Phase 0 evidence bundle

Phase 0 is complete. The [accepted baseline](accepted/7054f13/README.md) binds
five product profiles, the strict direct verifier, full-ML smoke, six freshly
installed offline-attested environments and forced generation rollback to clean
serving revision `7054f137f92c18676461242a18c8fc2619898b68`. Its four collector
artifacts share bundle ID
`sha256:5abee44ff9d4d85bd2c78de7b89e66668c4a1170aab9861eb5c56537b95111c1`.
The clean checkout passed 2,527 backend tests.

After an owner-provided fresh macOS session, one unchanged normal full smoke on
the target M4 Pro completed all eight steps, five profiles, both Qwen paths and
MP4 export. All 1,099 raw host observations have zero swapin, swapout and Metal
recovery counters; OOM was not observed. Cleanup completed, the disposable root
was empty and code SHA before/after matched. The 305.154-second host window
recorded peak process-tree RSS of 8,253,521,920 bytes and separate system-wide
Metal in-use peak of 11,172,855,808 bytes. RSS and Metal are non-additive.

The same-SHA five-profile batch and strict ten-case verifier remain unchanged:
three direct matches, seven model misses and zero infrastructure errors, with
completed worker retirement and cleanup. Model-quality guardrail failures and
insufficient critical-slice support remain in the accepted report. Acceptance
establishes a reproducible regression baseline; it is not model promotion or
evidence of generalization. Training and later phases remain inactive; a Phase 1
read-only data audit requires a separately authorized goal.

The [negative `7054f13` control](negative-controls/7054f13/README.md), its
[stage/RSS timeline](diagnostic-timeline.md), the separate no-ML sampler control
and the [earlier `1b11a54` controls](negative-controls/1b11a54/README.md) remain
unchanged. Their swap events were not subtracted or reclassified. A passing
fresh-session window does not identify the cause of those events or guarantee
zero swap for every future workload.

The collector never starts a model. It validates already produced JSON and
publishes one create-once directory containing:

- `baseline-snapshot.json`: code, frozen policy, dataset and profile bindings;
- `raw-measurements.json`: bounded process/Metal/swap/storage observations;
- `sanitized-report.json`: quality metrics, slices, guardrails and uncertainty;
- `error-ledger.json`: model misses separated from infrastructure failures.

All four documents share a deterministic `bundle_id`. They contain stable IDs,
hashes and measurements only: no local paths, API keys, source media, queries,
labels or raw model responses. The two committed datasets are
`regression_only`, never promotion evidence.

## Required inputs

The exact policy binding is read from
`../policies/phase0-regression-v1.json`; the collector does not hard-code a
policy revision or infer a dataset revision from a filename. Inputs are parsed
from the same bounded bytes whose SHA-256 is recorded.

The gate requires:

1. the policy-bound product regression dataset and video-verifier dataset;
2. a complete target-M4-Pro ML environment attestation;
3. a full-ML smoke receipt bound to the same clean `code_sha` before and after;
4. a direct strict/no-fallback video-verifier run with zero infrastructure errors;
5. actual complete run manifests with raw measurements for
   `lexical_qdrant`, `dense_siglip`, `temporal_refinement`, `lighthouse` and
   `qwen_verification`;
6. the owner-generated `phase0-baseline-receipt.json` binding those exact five
   manifest byte hashes, in order, to one policy, dataset, code SHA and pinned
   ML environment, with completed worker retirement and cleanup;
7. `internvideo` reported exactly as `not_configured` with
   `provider_not_configured` by the full smoke;
8. a rollback receipt generated by `scripts/phase0-rollback-proof.py`.

The environment receipt is pinned to the raw SHA-256 of the checked-in
`workers/ml-environment.lock.json`, every declared contract and canonical
identity, every environment dependency/distribution identity, every capability
model/runtime identity, and the exact `uv` binary identity. A syntactically
valid self-declared or stale attestation is rejected.

The baseline batch and full smoke must repeat the exact attestation ID, raw
manifest identity and role-to-environment bindings. The batch binds `owner`,
`vision_index`, `vision`, `whisper`, `ocr`, `lighthouse` and `qwen`; the smoke
binds the same roles except its unused `vision_index` role. A compatible-looking
substitute virtual environment, reordered run, changed run bytes or hand-edited
lifecycle claim is rejected. The exact batch shape is frozen in
`baseline-batch.schema.json`.

Runs must share code SHA, dataset revision, hardware, execution mode and
applicable common model/index identities. Each digest-sealed measurement
protocol is validated independently because its managed-worker set can differ
by profile. The profile-bound product environment and product runtime digests
are also validated by each profile's frozen identity contract and are
intentionally allowed to differ.

The full smoke must exercise the complete product receipt
`upload -> index -> search -> inspectable evidence -> MP4 export`, all five
executed profiles, and the exact eight component smoke steps. Raw host samples
must have a strictly increasing timeline, monotonic recovery/swap counters,
consistent bounded derived values, zero recovery/swap delta, no observed OOM
and process-tree RSS within the frozen policy ceiling.

The persisted full-smoke receipt is schema version `2`; schema version `1` is
deliberately rejected by the Phase-0 collector because it did not prove which
search components actually ran. Every executed profile receipt now contains one
exact, path-free `component_execution` object with this shape:

```json
{
  "schema_version": 1,
  "profile_identity": "<exact frozen profile identity>",
  "search_configuration_identity": "evaluation-search-configuration@1:<sha256>",
  "invoked_component_ids": [
    "text_vectors",
    "lexical_text",
    "visual_dense",
    "temporal_refinement",
    "lighthouse",
    "qwen_verification"
  ],
  "component_input_counts": {
    "text_vectors": 1,
    "lexical_text": 1,
    "visual_dense": 1,
    "temporal_refinement": 1,
    "lighthouse": 1,
    "qwen_verification": 1
  },
  "component_output_counts": {
    "text_vectors": 1,
    "lexical_text": 1,
    "visual_dense": 1,
    "temporal_refinement": 1,
    "lighthouse": 1,
    "qwen_verification": 1
  },
  "component_evidence_counts": {
    "text_vectors": 1,
    "lexical_text": 1,
    "visual_dense": 1,
    "temporal_refinement": 1,
    "lighthouse": 1,
    "qwen_verification": 1
  }
}
```

This example shows the fully selected `qwen_verification` profile; actual counts
may be any bounded values that satisfy the rules below.

The six canonical component IDs, in order, are `text_vectors`, `lexical_text`,
`visual_dense`, `temporal_refinement`, `lighthouse` and `qwen_verification`.
Selection is cumulative across the frozen ladder: `lexical_qdrant` selects the
first two; `dense_siglip` adds `visual_dense`; `temporal_refinement` adds its
named component; `lighthouse` adds `lighthouse`; and `qwen_verification` adds
`qwen_verification`. The invoked list must equal that exact ordered selection.
All three count maps must contain exactly the six keys. Counts are non-negative
JSON integers (booleans are invalid), every selected component must have
positive input, output and evidence counts, and every unselected component must
remain zero. Missing, extra, duplicate, reordered, foreign or path-bearing
values fail the whole smoke closed.

The collector normalizes these traces rather than retaining caller-controlled
field ordering. The normalized per-profile objects are preserved under
`full_ml_smoke.component_execution` in both `baseline-snapshot.json` and
`sanitized-report.json`, alongside the retained full-smoke `schema_version`, so
the committed evidence can be audited without raw queries, media, provider
output or local paths. Because this is a breaking extension of both aggregate
artifacts, `baseline-snapshot.json` and `sanitized-report.json` use schema
version `2`; their pre-trace schema version `1` must not be substituted.

## Capture and assemble

Use a private temporary directory so raw input receipts never enter the
repository. The checkout must be clean for both receipt generation and final
assembly.

```bash
phase0_private="$(mktemp -d)"
code_sha="$(git rev-parse HEAD)"

.venv/bin/python -I scripts/phase0-rollback-proof.py \
  > "$phase0_private/rollback-proof.json"

.venv/bin/python -I scripts/phase0-evidence.py \
  --policy docs/benchmarks/policies/phase0-regression-v1.json \
  --product-dataset docs/benchmarks/product-retrieval/seed-v1.json \
  --verifier-dataset docs/benchmarks/video-verifier/seed-v1.json \
  --environment-attestation "$phase0_private/ml-environment.json" \
  --full-ml-smoke "$phase0_private/full-ml-smoke.json" \
  --baseline-batch "$phase0_private/phase0-baseline-receipt.json" \
  --video-verifier-run "$phase0_private/video-verifier-run.json" \
  --benchmark-run lexical_qdrant="$phase0_private/lexical-qdrant.json" \
  --benchmark-run dense_siglip="$phase0_private/dense-siglip.json" \
  --benchmark-run temporal_refinement="$phase0_private/temporal-refinement.json" \
  --benchmark-run lighthouse="$phase0_private/lighthouse.json" \
  --benchmark-run qwen_verification="$phase0_private/qwen-verification.json" \
  --rollback-proof "$phase0_private/rollback-proof.json" \
  --output-dir "$phase0_private/baseline-bundle" \
  --code-sha "$code_sha"
```

The collector refuses an existing output directory and writes the four files
through a sibling temporary directory followed by an atomic rename. A success
response contains only `status`, `bundle_id` and `code_sha`; errors are
sanitized. A valid bundle is evidence for an owner review of the Phase-0 gate,
not permission to train or promote a model.

## Rollback proof

The proof helper runs only this exact pytest node:

```text
backend/tests/test_video_index_jobs_repository.py::test_failed_full_job_publish_keeps_prior_release_searchable_after_restart
```

It records the clean SHA and test-source SHA-256, suppresses raw pytest output,
and emits the fixed semantic assertions in `rollback-proof.schema.json`. It
fails if the test, source file or clean Git identity changes during execution.
